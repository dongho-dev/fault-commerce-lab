# CS-02 주문 트랜잭션 수정 검증

검증일: 2026-10-06 (Asia/Seoul). 대상: 이슈 [#10](https://github.com/dongho-dev/fault-commerce-lab/issues/10).

## 원인과 수정

`incident/cs-02`의 재고 차감은 주문 저장 전에 별도 트랜잭션으로 커밋되었다. 이후 주문 저장에 실패하면 주문 트랜잭션만 롤백되어 재고 차감이 남았다.

`app/services/order.py`에서 두 작업을 같은 `session.begin()` 범위로 합쳤다. 주문 서비스 소스는 정상 기준 `l1-baseline-v2`와 일치한다. 주문 저장 실패 주입 장치와 검증 기대값, Oracle, 기존 테스트, API 계약 및 DB 스키마는 변경하지 않았다.

## 실제 재실행 결과

현재 체크아웃으로 수정 전후를 각각 빌드하고, 격리된 PostgreSQL과 Linux Chromium에서 동일한 `LAB02-Fail` 주문 저장 실패 조건을 실행했다.

| 단계 | 주문 응답 | 실패 상품의 확정 주문 수량 | 실패 후 재고 | Oracle |
| --- | --- | --- | --- | --- |
| 수정 전 | 500 | 0 | 2 → 1 | 불일치 탐지 |
| 수정 후 | 500 | 0 | 2 → 2 | 통과 |

수정 후 정상 주문 대조군은 201, 주문 수량 1, 재고 2 → 1로 통과했다. 실패 주문이 브라우저 주문내역에 남지 않고 입력 우편번호가 유지되는 검사도 통과했다.

- 수정 전: `python -m lab_suite.operator check --expect fault --fresh` 통과.
- 수정 후: `python -m lab_suite.operator check --expect healthy --fresh` 통과.
- 별도 임시 테스트 DB의 기존 회귀 테스트 5개 통과: 정상 주문/가격 스냅샷, 재고 부족, 주문 저장 예외 롤백, 단일 상품 동시 주문, 두 상품 동시 주문.
- 단일 상품 동시 요청 40건: 성공 10건, 재고 부족 30건, 연결 오류 0건, 잔여 재고 0개.
- 변경 파일 Ruff 검사 및 포맷 검사 통과. pytest에는 Starlette/AnyIO 의존성의 폐기 예정 경고 1건이 있었다.

실행 시각, 앱 이미지 ID, 소스 SHA-256, 전후 probe 원본과 회귀 테스트 출력은 [검증 증거](evidence/02/transaction-fix.json)에 보존했다.

## 범위

새 임시 DB에서 수정 효과를 검증했다. 장애 중 이미 발생한 재고 불일치의 데이터 복구는 수행하지 않았다. 전체 저장소 테스트 모음은 실행하지 않았다. 자동 브라우저 검증은 Linux 컨테이너 안에서 수행했다.
