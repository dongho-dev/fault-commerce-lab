# CS-03 배송비 계산과 서버 견적

이 문서는 `incident/cs-03`에서 수행한 수정과 검증 기록이다.
[수정 PR #21](https://github.com/dongho-dev/fault-commerce-lab/pull/21)은 해당 실습 브랜치에
병합되었다. 아래 `lab_suite` 실행 명령과 로컬 증거 경로는 그 실습 체크아웃 기준이며,
기본 브랜치의 집중 검증 방법은 저장소 README를 따른다.

## 원인과 수정

`incident/cs-03`은 서버에서 우편번호 전체를 정수로 바꾼 뒤 문자열로 되돌렸다.
`06236`이 `6236`으로 바뀌어 지역 판정에 `06` 대신 `62`를 사용했고, 2,500원을
추가했다. 정상 기준 `l1-baseline-v2`와 같이 앞자리 0을 보존하도록 수정했다.

문제는 숫자 문자열의 앞자리 0을 제거한 결과 지역 접두어가 60 이상으로 바뀌는
입력에서 발생한다. `06236`, `06000`, `00060` 등이 포함되며, 상품금액 20만 원
이상이어도 잘못된 지역 추가비는 남는다. 모든 0으로 시작하는 우편번호가 영향을
받는 것은 아니다. 예를 들어 `05999`는 변환 전후 모두 추가비 대상이 아니다.

주문 전 표시에는 별도의 JavaScript 계산식이 있었다. 이 계산식을 제거하고
`POST /orders/quote`가 DB의 상품 단가, 수량, 우편번호를 이용해 견적을 반환하도록
했다. 견적과 주문 생성은 `OrderService._calculate_quote`를 함께 사용한다.
기존 `POST /orders`의 요청·응답 계약, Oracle, DB 불변조건은 유지한다.

견적 요청은 주문 생성이나 재고 예약을 하지 않는다. 브라우저는 상품별 서버
견적을 합산하며, 현재 입력에 대한 견적이 준비되기 전에는 주문을 제출하지 않는다.
입력 변경으로 이전 견적을 무효화하고 실패하면 재시도할 수 있게 한다.
서버의 가격·정책을 별도로 수정하지 않고 입력이 같다면 견적과 주문 금액은 같다.
견적은 가격을 고정하는 계약이나 재고 예약이 아니다.

## 검증 기준

- 앞자리 0, 우편번호 접두어 59/60 경계, 상품금액 199,999/200,000원,
  수량 2/3개, 무료배송과 추가비의 조합을 검증한다.
- 견적·주문 응답·DB 저장 금액 및 우편번호의 일치를 확인한다.
- 반복 견적이 재고나 주문 수를 바꾸지 않고, 클라이언트가 보낸 임의 가격을
  계산 기준으로 사용하지 않는지 확인한다.
- 기존 주문의 재고 차감, 재고 부족, 저장 실패 시 롤백을 회귀 검증한다.
- 브라우저에서 견적 대기·실패·재시도와 늦은 응답을 확인한다.
- `python -m lab_suite.operator check --expect healthy --fresh`로 현재 코드를
  빌드해 실제 API·DB·Linux Chromium 경로를 확인한다. 기존 CS-03 금액 기대값은
  유지하고, 화면 검사는 비동기 견적 완료를 기다린 후 금액을 읽는다.

## 기존 주문을 확인할 기준

이번 변경은 이미 저장된 주문이나 브라우저 주문내역을 자동으로 수정하지 않는다.
이전 주문은 **주문에 저장된 단가·수량·우편번호**로 당시 실습 정책을 적용해
기대 배송비와 총액을 계산하고 저장값과 비교한다. 현재 상품 단가로 과거 주문을
재계산하지 않는다.

정상 배송비는 상품금액이 20만 원 미만일 때 기본 3,000원, 원본 우편번호의 숫자
앞 두 자리가 60~99이면 추가 2,500원, 수량 3개째부터 개당 추가 700원이다.
20만 원 이상이면 기본 배송비만 면제된다. 예상 총액은 저장 단가 × 수량 + 정상
배송비다. 불일치 주문은 별도 확인 대상으로 남기며 DB를 직접 덮어써 해결을
연출하지 않는다. 새 임시 DB의 검증 통과는 과거 주문 데이터 복구의 증거가 아니다.

## 고객 안내 예시

일부 우편번호를 처리하는 과정에서 앞자리 0이 빠져 배송비 2,500원이 잘못
추가되는 오류를 수정했습니다. 주문 전 안내와 주문 접수에 같은 계산 기준을
적용했습니다. 기존 주문의 금액은 접수 당시 상품 단가·수량·우편번호를 기준으로
별도 확인해야 합니다. 이 실습 쇼핑몰에서는 실제 결제가 이루어지지 않습니다.
