# CS 심화 장애 조사 문제

고객에게 드러나는 하나의 문제를 조사하고 수정하는 학습용 가상 사례다. 기존 CS-01~10 이후의 심화 과정으로, 새 문제는 CS-11부터 번호를 이어 사용한다.

정상 기준은 변경하지 않은 l1-baseline-v2다. 각 실습은 전용 브랜치와 격리된 앱·DB에서 실행한다. 실습 준비 검증과 학습자의 문제 해결 완료는 별도로 기록한다.

**검증 상태는 각 GitHub 이슈와 [준비 검증 기록](labs/advanced-verification.md)을 따른다.**

문제를 해결한 뒤 재현 조건, 수정 내용과 정상 동작을 확인한 근거를 남긴다. 기존 API 계약, Oracle과 DB 불변조건은 유지한다.

### 문제 11. 재고가 넉넉한 상품인데 주문을 완료하지 못하는 고객이 있습니다

#### CS팀 VOC 요약

같은 상품을 구매하려던 고객 중 일부에게 주문을 완료하지 못했다는 안내가 나타났습니다. 해당 시간에 정상적으로 주문을 마친 고객도 있었고, 이후 상품 화면에는 여전히 구매 가능한 수량이 표시됩니다.

#### 고객 문의

1. “하나만 주문했는데 서버 오류라는 안내가 나왔어요. 상품 화면에 다시 들어가도 아직 여러 개 남아 있다고 보여요.”
2. “같이 사려던 동료는 주문번호가 나왔는데 저는 완료하지 못했어요. 제 주문은 접수된 건가요?”

#### CS팀 확인 사항

- 같은 시간대에 같은 상품을 한 개씩 주문한 고객에게 완료 화면과 오류 화면이 각각 나타났습니다.
- 문의에 포함된 상품의 남은 수량은 주문 전후 모두 요청 수량보다 많았습니다.
- 오류 안내를 받은 고객의 같은 브라우저 주문내역에는 해당 주문이 보이지 않습니다.
- 상품 검색과 상세 화면은 해당 시간에도 열렸습니다. 오류가 난 모든 주문의 최종 접수 상태는 아직 확인하지 못했습니다.

#### 요청

주문을 완료하지 못한 고객의 최종 접수 상태를 확인하고, 구매 가능한 상품을 정상적으로 주문할 수 있도록 복구해 주세요. 영향을 받은 고객에게 재주문 여부를 안내할 수 있는 확인 결과도 정리해 주세요.

### 문제 12. 한정 수량보다 많은 주문이 접수됩니다

#### CS팀 VOC 요약

남은 수량이 적은 상품을 함께 구매한 고객들이 각자 주문 완료 화면을 받았습니다. 제출된 주문 수량을 합치면 당시 안내된 판매 가능 수량보다 많아, 완료된 주문을 믿어도 되는지 문의하고 있습니다.

#### 고객 문의

1. “한정 수량 상품을 주문했고 주문번호도 받았어요. 그런데 준비된 수량보다 주문이 많이 들어왔다며 확인이 필요하다고 하네요.”
2. “주문 완료 화면까지 봤는데 제 주문도 정상적으로 처리되는 건가요?”

#### CS팀 확인 사항

- 제출된 완료 화면에는 서로 다른 주문번호가 표시되어 있습니다.
- 문의 상품의 판매 시작 수량과 이후 추가 입고가 없었다는 점은 확인했습니다.
- 확인된 완료 화면의 합계 수량이 해당 판매 수량보다 많습니다.
- 각 고객은 주문하기를 한 번씩 눌렀다고 설명했습니다. 같은 현상이 모든 상품에서 나타나는지는 확인하지 못했습니다.

#### 요청

완료된 주문과 판매 가능한 수량을 확인하고, 확보된 수량 안에서 정확하게 주문이 접수되도록 복구해 주세요. 이미 접수된 주문의 영향 범위와 고객에게 안내할 내용을 정리해 주세요.

### 문제 13. 다시 방문하니 상품 화면을 열 수 없습니다

#### CS팀 VOC 요약

조금 전까지 보이던 상품을 다시 확인하려고 하면 상품 목록과 상세 화면을 불러오지 못한다는 문의입니다.

#### 고객 문의

1. “아까 보던 상품을 다시 열었는데 이제 상품 정보가 안 나와요.”
2. “새로고침도 하고 새 창에서도 열어 봤는데 계속 못 보고 있어요.”

#### CS팀 확인 사항

- 같은 상품을 정상적으로 확인했던 뒤 다시 방문했을 때 문제가 나타났습니다.
- 새로 연 창에서도 상품 정보를 불러오지 못했습니다.
- 잠시 기다렸다가 다시 시도해도 같은 증상이 이어졌습니다.

#### 요청

다시 방문하거나 새로고침한 고객도 상품 목록과 상세 정보를 정상적으로 확인할 수 있게 해 주세요.
